# Docker 基础 — 为什么需要一个"迷你电脑"？

> 你已经在 [0.3_GitHub和Git](../0_getting_started/0.3_github_and_git.md) 里看到了"菜谱 vs 厨房"的类比。这章从实操角度解释 Docker —— 你天天跑的 `bash scripts/start.sh` 到底在干什么。

---

## 问题：为什么不用 apt 直接装 Isaac Sim？

```bash
# 你可能会想：
sudo apt install isaac-sim-5.1    # ❌ 不存在这个包！
```

Isaac Sim 不是普通的 Linux 软件。它是一整套仿真引擎——包含 Python 3.10、NVIDIA 渲染管线、物理引擎、数百个依赖库。它不能简单地 `apt install`。

更关键的是：**Isaac Sim 官方只支持 Ubuntu 22.04 和 24.04**。你的系统可能是 26.04（太新）或 20.04（太旧）。

Docker 的解决方案：在容器里跑一个**迷你 Ubuntu 24.04**，Isaac Sim 在里面完美运行，不受你宿主机系统的影响。

---

## 三个核心概念

### 镜像 (Image)
"一个打包好的环境"——包含 Ubuntu、Isaac Sim、所有依赖。23GB。

```
镜像 = 23GB 的 .tar.gz 文件（存在 NGC 上）
     = "环境的快照"
     = 模板
```

### 容器 (Container)
"镜像跑起来的实例"——每次 `docker run` 都从镜像创建一个新容器。

```
镜像 → docker run → 容器（运行中）
       docker run → 容器（又一个，独立的）
       docker run → 容器（再来一个）
```

**容器是临时的**——退出就没了（除非你加了 `--rm` 以外的参数）。

### Dockerfile
"怎么构建镜像的说明书"——纯文本文件，Git 可以管。

```
Dockerfile（文本，几百行） → docker build → 镜像（二进制，23GB）
                                          → docker push → NGC / Docker Hub
```

## `docker run` 逐参数解释

这是 `start.sh` 里的 docker run 命令（简化版）。**每个参数都解释**：

```bash
docker run \
  --rm \                         # 容器退出后自动删除（不留垃圾）
  --gpus all \                   # 把所有 GPU 都分给这个容器
  --user 0:0 \                   # 以 root 用户运行（Isaac Sim 需要）
  -e ACCEPT_EULA=Y \             # 设环境变量：接受用户协议
  -e OMNI_KIT_ALLOW_ROOT=1 \     # 设环境变量：允许 root 运行 Kit
  --network=host \               # 容器用宿主机的网络（少一层 NAT）
  -v /host/path:/container/path \  # 挂载：把宿主机的文件夹"映射"到容器里
  nvcr.io/nvidia/isaac-sim:5.1.0 # 用这个镜像
  bash                            # 启动后执行 bash
```

### `-v` 挂载 —— 最关键的一个

```
宿主机（你的真实电脑）              容器（Docker 里的迷你 Ubuntu）
┌─────────────────────────┐      ┌─────────────────────────┐
│ ~/projects/g1-rl/sim/   │ ←──→ │ /sim/                   │
│ ~/projects/g1-rl/logs/  │ ←──→ │ /isaac-sim/logs/        │
│ ~/.cache/isaac-sim/kit/ │ ←──→ │ /isaac-sim/kit/cache/   │
└─────────────────────────┘      └─────────────────────────┘
        同一个文件！                    同一个文件！
```

**你在宿主机改代码 → 容器里立刻能看到**。容器退出后，日志留在宿主机上（不会随容器一起删除）。

## 这个项目实际怎么跑容器？

`scripts/start.sh` 封装了所有复杂的 docker run 参数。你只需要：

```bash
bash scripts/start.sh shell     # 进入容器的交互式终端
bash scripts/start.sh train     # 在容器里跑训练
bash scripts/start.sh visualize # 在容器里打开 Isaac Sim 3D 编辑器
```

想知道 `start.sh` 里面每行都在干什么？→ [3.3_逐行读启动脚本](../3_g1_project/3.3_read_start_sh.md)

## 常见问题

### Q: 每次 `docker run` 都会重新下载 23GB 的镜像吗？
**不会。** 镜像只在第一次 `docker pull` 时下载。之后 `docker run` 直接从本地缓存启动，秒级。

### Q: 容器里装的东西退出后就没了？
**默认是的。** 但 `-v` 挂载的目录会保留在宿主机上。我们项目的训练日志（`logs/`）就是通过挂载持久化的。

### Q: `docker images` 看到好多 <none> 标签的镜像？
这是旧版本的"悬空镜像"。清理：
```bash
sudo docker system prune -a
```

## 用 docker compose 一键启动

手写 `docker run` 参数太长容易出错。`docker compose` 把参数写进 YAML 文件：

```bash
# 一条命令代替 50 行 docker run 参数
docker compose -f docker/docker-compose.yml up
```

配置在 `docker/docker-compose.yml` 里——这个文件也是纯文本，Git 可以管。
