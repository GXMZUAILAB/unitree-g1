# Python 是怎么跑的 — 你不需要 Conda

> 新手常见的困惑："教程里又是 conda 又是 Docker 又是 pip，哪个才是我的 Python？"

---

## 一句话：训练在 Docker 里跑，Python 是 Docker 自带的

```
你敲了: bash scripts/start.sh train

实际发生了什么:
  start.sh → docker run ... → 容器启动 → 容器内的 Python 3.10 执行 train.py
                                                    ↑
                                    这个 Python 是 Isaac Sim 镜像自带的
                                    在 /isaac-sim/kit/python/bin/python3
                                    和你的宿主机没有任何关系
```

**你不需要在自己电脑上装 Python 3.10。Docker 容器里已经带了。**

---

## 为什么这个项目用 Docker 而不用 Conda？

| 方案 | 做法 | 优点 | 缺点 |
|------|------|------|------|
| Conda 本地 | 在自己电脑上装 Python 3.10 + Isaac Lab | ~10GB 下载量 | Ubuntu 26.04 不兼容 Isaac Sim |
| **Docker（本项目）** | 拉一个 23GB 的镜像，里面 Ubuntu 24.04 + Python 3.10 + Isaac Sim 全有了 | **不受宿主机版本影响** | 镜像大，首次下载慢 |

你选 Docker 是因为 Ubuntu 26.04 太新了——Isaac Sim 官方只支持 22.04/24.04。Docker 在容器里跑了一个虚拟的 24.04，Isaac Sim 在里面完美运行。

---

## 那 pip install 是在哪跑的？

```bash
bash scripts/start.sh install
```

这条命令**也是在 Docker 容器里跑的**。它在容器内执行：

```bash
/isaac-sim/kit/python/bin/python3 -m pip install gymnasium rsl-rl-lib
```

包装到宿主机的一个持久化目录（`~/.cache/isaac-sim/pip_pkgs/`），容器删了包还在。

---

## 宿主机上的 Python 呢？

宿主机自带 Python 3.14，但这个项目**从来不用它**。

你唯一可能用到宿主机 Python 的场景：
- **看 TensorBoard**：`pip install tensorboard && tensorboard --logdir ...`
  - 这用系统的 Python 就行，一行 `pip install`
  - 不需要 Conda

---

## 那 setup_miniconda.sh 是干嘛的？

`scripts/setup_miniconda.sh` 是项目初始化时建的——作为"备选方案"，以防将来需要。但到目前为止，**没有一条训练命令依赖它**。

你可以完全不跑 `setup_miniconda.sh`，训练照样正常工作。

---

## 总结

| 你在想... | 实际情况 |
|-----------|----------|
| "我需要装 Python 3.10 吗？" | 不需要。Docker 镜像自带 |
| "我需要在宿主机装 Conda 吗？" | 不需要。训练全在 Docker 里跑 |
| "那我 pip install 用什么？" | `bash scripts/start.sh install`——在容器里装 |
| "宿主机 Python 3.14 能删吗？" | 别删系统 Python，但不需要用它 |
