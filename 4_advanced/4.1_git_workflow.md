# Git 协作流程 — 菜谱的多人合写

> 你已经会用 `git clone/pull/commit/push` 了。但当 4 个人同时改代码时，需要再多懂几个概念。

---

## 分支（Branch）— 同时改不同东西，互不干扰

**问题**：你在改奖励函数，队友在改地形配置。你俩都改 `velocity_env_cfg.py`——Git 该听谁的？

**解决**：每人开一个分支。分支 = 代码的"平行宇宙"。

```
main 分支（稳定版）:
  A → B → C → D
       ↘
小明/调奖励:
         E → F → G
  
小红/加地形:
         H → I
```

### 一行命令开分支

```bash
git checkout -b xiaoming/reward-tuning    # 创建并切换到新分支
# 现在你在这个分支上的所有改动都不会影响 main
```

### 合并回 main

```bash
git checkout main                          # 先回到 main
git merge xiaoming/reward-tuning           # 把分支的改动合并进来
```

---

## Pull Request（PR）— 让队友审查你的改动

**问题**：你改完了想合进 main，但万一改错了呢？

**流程**：
1. 你把分支推送到 GitHub
2. 在 GitHub 网页上点"New Pull Request"
3. 队友看到你的改动，评论、提意见
4. 审查通过 → 合并

```bash
git push origin xiaoming/reward-tuning   # 推送分支到 GitHub
# 然后去 GitHub 网页操作
```

---

## 冲突（Conflict）— 你和队友改了同一行

```
你改了第 50 行: track_lin_vel_xy_exp weight=2.0
队友改了第 50 行: track_lin_vel_xy_exp weight=0.5

Git: "我不知道该听谁的——你自己来选"
```

Git 会在文件里标出冲突位置：

```
<<<<<<< HEAD
track_lin_vel_xy_exp = RewTerm(weight=2.0, ...)
=======
track_lin_vel_xy_exp = RewTerm(weight=0.5, ...)
>>>>>>> xiaohong/new-terrain
```

你手动编辑文件，删掉标记，保留你选的行。然后 commit。

---

## 团队日常流程

```bash
# 早上来：
git checkout main && git pull          # 拉最新代码

# 开始干活：
git checkout -b feature/xxx            # 开新分支
# ... 写代码、跑实验 ...

# 提交：
git add . && git commit -m "调大速度跟踪权重，reward 从 5 升到 12"
git push origin feature/xxx

# 去 GitHub 创建 PR → 等队友 review → 合并
```

---

## Git 不止 4 条命令了

| 命令 | 什么时候用 |
|------|-----------|
| `clone` / `pull` / `add` / `commit` / `push` | 单人开发——入门就够 |
| `branch` / `checkout -b` | 开始做新功能时 |
| `merge` | 合并分支 |
| `stash` | 临时保存未完成的改动，切去干别的事 |
| `log --oneline` | 看提交历史 |
| `diff` | 看具体改了什么 |

**现在不需要。** 你一个人调参、一个人训练时，用基本的 `clone/commit/push` 绰绰有余。
