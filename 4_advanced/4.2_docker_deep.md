## 镜像分层 — 为什么每次 pull 不用重新下 23GB？

Docker 镜像不是一整坨。它是一层一层叠起来的——像千层蛋糕。

```
你的训练镜像:
┌──────────────────────────────────┐
│ 第 6 层: pip install gymnasium   │ ← 你的改动
├──────────────────────────────────┤
│ 第 5 层: COPY scripts/           │ ← 你的脚本
├──────────────────────────────────┤
│ 第 4 层: NVIDIA 装的 CUDA 库     │
├──────────────────────────────────┤
│ 第 3 层: NVIDIA 装的渲染引擎     │
├──────────────────────────────────┤
│ 第 2 层: Ubuntu 24.04 系统库     │
├──────────────────────────────────┤
│ 第 1 层: Ubuntu 24.04 基础文件   │ ← 20GB，从 NGC 拉取
└──────────────────────────────────┘
```

**关键好处**：
- 底层（Ubuntu）不变 → 只下载一次
- 你只改了第 5-6 层 → 重新构建时只重建这两层，下面 4 层用缓存
- 多人用同一基础镜像 → 只存一份 Ubuntu 24.04，各人的改动是上面叠加的薄层

## Dockerfile 逐指令解释

`docker/Dockerfile`（本项目的）：

```dockerfile
# 行1: 基础镜像 — 从 NGC 的 Isaac Sim 5.1.0 开始
FROM nvcr.io/nvidia/isaac-sim:5.1.0

# 行2: RUN — 在镜像构建时执行命令
# 把 gymnasium 等 RL 库装到持久化目录（用 volume 挂载时在宿主机上）
RUN /isaac-sim/kit/python/bin/python3 -m pip install \
    --target /isaac-sim/pip_pkgs \
    gymnasium rsl-rl-lib==5.0.1 argcomplete

# 行3: COPY — 把本地文件拷进镜像
COPY scripts/ /workspace/scripts/
RUN chmod +x /workspace/scripts/*.sh

# 行4: ENV — 设默认环境变量（运行时可以用 -e 覆盖）
ENV ACCEPT_EULA=Y OMNI_KIT_ALLOW_ROOT=1

# 行5: WORKDIR — 设默认工作目录
WORKDIR /workspace

# 行6: CMD — 容器启动时默认执行的命令（可以被 --entrypoint 覆盖）
CMD ["bash"]
```

| 指令 | 什么时候执行 | 类比 |
|------|------------|------|
| `FROM` | 构建时 | 选一个基础厨房 |
| `RUN` | 构建时 | 在厨房里装工具 |
| `COPY` | 构建时 | 把你的菜谱贴到厨房墙上 |
| `ENV` | 运行时 | 设定温控器的默认温度 |
| `CMD` | 运行时 | 厨师进厨房后默认做什么 |

## 构建和推送

```bash
# 构建镜像
docker build -f docker/Dockerfile -t g1-rl-train:v1.0 .

# 测试
docker run --rm --gpus all g1-rl-train:v1.0 bash scripts/start.sh train

# 推送到 Docker Hub（需要注册 hub.docker.com 账号）
docker login
docker tag g1-rl-train:v1.0 yourname/g1-rl-train:v1.0
docker push yourname/g1-rl-train:v1.0
```

推送后别人只需：
```bash
docker pull yourname/g1-rl-train:v1.0
docker run --rm --gpus all yourname/g1-rl-train:v1.0
```

不需要配 Conda、不需要装 Python、不需要 git clone——镜像里全有了。

## Docker Compose — 把 run 参数写进文件

`docker/docker-compose.yml` 就是把 `docker run` 的参数结构化：

```yaml
services:
  g1-train:
    build: .                   # 从当前目录的 Dockerfile 构建
    runtime: nvidia            # --gpus all
    volumes:
      - ./logs:/isaac-sim/logs # -v ./logs:/isaac-sim/logs
    environment:
      - ACCEPT_EULA=Y          # -e ACCEPT_EULA=Y
```

优点：不用记参数、可以版本控制、一条 `docker compose up` 全部搞定。

## 常见坑

### 改了 Dockerfile 但构建没变化
→ 加 `--no-cache` 强制重构建：
```bash
docker build --no-cache -t g1-rl-train:v1.0 .
```

### 镜像太大了
→ 用 `.dockerignore` 排除不需要的文件（`logs/`, `models/`, `__pycache__/`）
→ 合并多个 RUN 命令到一行

### GPU 在容器里看不到
→ 确保 build 的镜像基于 NGC 的 Isaac Sim（自带 CUDA），不要用 `FROM ubuntu:24.04`
