# 5.6 在机器人上编译

> 你已经把代码推到了机器人上。现在，把 C++ 代码变成机器人能运行的**可执行文件**。

---

## 类比：做菜之前先买原材料

```
代码 = 食谱（文字，人能看懂）
编译 = 按食谱准备食材（机器能看懂的过程）
可执行文件 = 成品菜（直接吃/运行）
```

C++ 和 Python 不一样。Python 代码写完了直接 `python3 xxx.py` 就能跑。C++ 需要一个叫 **"编译器"** 的程序把源码翻译成二进制文件。

这个过程叫 **编译（build）**。在 Linux 上用 `cmake` + `make` 两个工具完成：

- `cmake` = "根据食谱列出需要的所有食材，生成采购清单"
- `make` = "按采购清单去买菜、切菜、炒菜"
- 产出的 `g1_ctrl` = "做好的菜"（可执行文件）

---

## 前提：你已经在机器人上了

按照 [5.2](5.2_connect_to_robot.md) 连上机器人：

```bash
ssh unitree@<机器人IP>
```

你已经把 `deploy/` 文件夹推到了机器人的 `~/g1-rl-deploy/` 下（用 `scripts/deploy.sh push`）。

```bash
# 确认文件都在
ls ~/g1-rl-deploy/
# 应该看到：include/  g1_29dof/  install_onnxruntime.sh  README.md
```

---

## 第一步：确认架构 + ONNX Runtime

G1 的机载电脑是 **ARM64（aarch64）**，不是 x86_64。`deploy/thirdparty/` 下同时存放了两种架构的 ONNX Runtime，CMake 会自动选择正确的。**不需要手动设环境变量**。

### 如果机器人能联网

```bash
cd ~/g1-rl-deploy
bash install_onnxruntime.sh
```

### 如果机器人不能联网（常见情况）

机器人在实验室里通常没有外网。在**你自己的电脑**上下载：

```bash
cd ~/projects/g1-rl/deploy/thirdparty
wget https://github.com/microsoft/onnxruntime/releases/download/v1.22.0/onnxruntime-linux-aarch64-1.22.0.tgz
tar xzf onnxruntime-linux-aarch64-1.22.0.tgz
```

然后通过 `rsync` 推送到机器人（或者直接用 `scripts/deploy.sh push`）即可。

> 路径对比：
> - x86_64（你电脑）: `deploy/thirdparty/onnxruntime-linux-x64-1.22.0/`
> - ARM64（机器人）: `deploy/thirdparty/onnxruntime-linux-aarch64-1.22.0/`

---

## 第二步：检查编译工具是否齐全

```bash
# 逐个检查
cmake --version        # 应该有版本号输出
g++ --version          # 应该有版本号输出
make --version         # 应该有版本号输出
```

如果哪个命令报 `command not found`，就装它：

```bash
sudo apt install cmake build-essential -y
```

> `build-essential` 里包含了 `g++` 和 `make`，不用分开装。

---

## 第三步：编译

```bash
# 确认 deploy/ 代码已经 rsync 到机器人上
ls ~/g1-rl-deploy/g1_29dof/CMakeLists.txt

# 清理旧的 cmake 缓存（如果有的话）
cd ~/g1-rl-deploy/g1_29dof
rm -rf build
mkdir build && cd build

# 生成构建文件（CMake 会自动检测 ARM64 / x86_64 选择正确的 ONNX Runtime）
cmake .. -DCMAKE_BUILD_TYPE=Release

# 开始编译（-j 用上所有 CPU 核心）
make -j$(nproc)
```

### 正常的话你会看到什么

```
[ 25%] Building CXX object CMakeFiles/g1_29dof_controller_lib.dir/src/State_RLBase.cpp.o
[ 50%] Building CXX object CMakeFiles/g1_29dof_controller_lib.dir/src/State_Mimic.cpp.o
[ 75%] Linking CXX static library libg1_29dof_controller_lib.a
[100%] Building CXX object CMakeFiles/g1_ctrl.dir/main.cpp.o
[100%] Linking CXX executable g1_ctrl
[100%] Built target g1_ctrl
```

最后一行 `Built target g1_ctrl` 出现，说明编译成功。检查一下：

```bash
ls -lh ./g1_ctrl
# -rwxr-xr-x ... g1_ctrl  ← 这就是你刚编译出来的可执行文件
```

## 报错了怎么办？

以下是常见编译错误的简单处理：

| 报错信息 | 什么意思 | 怎么办 |
|---------|---------|-------|
| `cmake: command not found` | 没装 cmake | `sudo apt install cmake -y` |
| `fatal error: unitree/dds_wrapper/...` | SDK 头文件缺失 | deploy/include/unitree/ 在 rsync 推送时是否完整？ |
| `fatal error: onnxruntime_cxx_api.h` | ONNX Runtime 头文件未找到 | CMake 自动检测架构失败，检查 `cmake ..` 输出中的 `ONNXRUNTIME_ROOT` |
| `undefined reference to get_type_props<unitree_go::...>` | libunitree_sdk2.a 版本不匹配（旧版） | 确认 ~/g1-rl-deploy/g1_29dof/lib/libunitree_sdk2.a 存在且在 `cmake ..` 输出中被引用 |
| `cannot find -lboost_program_options` | 缺少 Boost 库 | `sudo apt install libboost-program-options-dev -y` |
| `cannot find -lyaml-cpp` | 缺少 yaml-cpp | `sudo apt install libyaml-cpp-dev -y` |
| `cannot find -lddsc` | 缺少 DDS 库 | 联系管理员安装 CycloneDDS，或从 unitree_sdk2/thirdparty 复制 |

其他看不懂的错误，去 [5.8 排错速查](5.8_troubleshooting.md) 找。
