## 核心问题：惩罚/奖励比 = 8:1

**惩罚权重合计 -24.4，奖励合计 +3.15，惩罚是奖励的 8 倍。**

策略学到的不是"怎么走更快"，而是"怎么不触发惩罚"。最优解就是保持初始姿态不动——这完美解释了 play 时的僵尸表现。

### 最严重的三个惩罚

1. **base_height=-10.0**：站 0.78m 误差一点就扣大分。策略不敢改变重心高度
2. **flat_orientation_l2=-5.0**：身体歪了就扣分。人形机器人走路不可能完全水平，策略不敢迈步
3. **joint_deviation_waists=-1.0 + legs=-1.0**：腰和腿偏离默认位置就扣分。但走路恰恰需要偏离默认位置

## 推荐调整

| Reward 项 | 当前 | 建议 | 理由 |
|-----------|:----:|:----:|------|
| action_rate | -0.05 | **-0.01** | 减小爆炸触发点 |
| joint_deviation_waists | -1.0 | **-0.2** | 走路需要腰动 |
| joint_deviation_legs | -1.0 | **-0.2** | 走路需要腿动 |

| **惩罚/奖励比** | **8:1** | **~1.7:1** | 正常范围 |

## action_rate_l2 爆炸分析（技术细节）

`action_rate_l2` 的实现（IsaacLab rewards.py:252-254）：

```python
def action_rate_l2(env):
    return torch.sum(torch.square(env.action_manager.action - env.action_manager.prev_action), dim=1)
```

29 个关节的 PD 目标位置的差值平方和。正常：每个 delta ~ 0.1，29 × 0.01 = 0.29，×(-0.05) = **-0.0145**。

炸到 -5.49×10²⁵ 意味着 `||a - a_prev||² ≈ 10²⁷`，即每个关节动作跳 ~10¹³。唯一可能：网络某隐藏层权重出现了极大值 → 前向传播输出爆炸 → 动作值爆炸。

**预防**：降低权重 + 梯度裁剪 + 激活函数选择 ELU 而非 ReLU（ELU 不会像 ReLU 那样无上限）。
